# Court v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an installable, mobile-first Court v1 PWA that presents current ATP/WTA tennis information through a provider-neutral free-data layer and adds personal follows, Watch/Watched, spoiler protection, notes, broadcast information, and Dropbox-ready export.

**Architecture:** A Vite + vanilla TypeScript PWA renders the four Court destinations and consumes only normalized Court-domain objects. A Supabase Edge Function acts as the secure tennis-data broker/cache and can swap or combine free data providers without UI changes. Supabase stores only personal Court state plus a modest API cache; Dropbox export is generated from that personal state.

**Tech Stack:** Vite, TypeScript, Vitest, jsdom, Supabase Postgres/Auth/Edge Functions, CSS custom properties, Lucide icons, GitHub Pages, Web App Manifest, Service Worker.

**Spec:** `docs/superpowers/specs/2026-09-07-court-v1-design.md`

## Global Constraints

- Court v1 must work without paid tennis API access.
- No core feature may silently require a paid endpoint.
- Court always opens to Today.
- Singles are primary; doubles are optional.
- Primary navigation is Today · Tour · Players · Watch.
- UI code must not call vendor-specific tennis APIs directly.
- Provider secrets must never appear in browser code or GitHub.
- Supabase stores personal Court state and a modest cache, not a full tennis archive.
- Dropbox backup/export contains irreplaceable personal data only.
- Watch and Star remain distinct.
- Watchlisted matches are spoiler-protected automatically.
- Global Spoiler Mode hides results throughout the app.
- Nationality does not affect relevance ranking.
- Deep paid-only match analytics are not a v1 dependency.
- Draws are included only if free data proves reliable.
- IBM Plex Sans is the primary UI typeface; IBM Plex Mono is used for numeric tennis data.

```ts
export type Route =
  | { name: "today" }
  | { name: "tour" }
  | { name: "players" }
  | { name: "watch" }
  | { name: "match"; id: string }
  | { name: "player"; id: string }
  | { name: "tournament"; id: string };

export function parseRoute(hash: string): Route {
  const path = hash.replace(/^#\/?/, "");
  if (!path) return { name: "today" };
  const [name, id] = path.split("/");
  if ((name === "match" || name === "player" || name === "tournament") && id) {
    return { name, id };
  }
  if (name === "tour" || name === "players" || name === "watch") {
    return { name };
  }
  return { name: "today" };
}
```

```ts
export function relevanceScore(match: TennisMatch, state: PersonalState, significant: (round?: string) => boolean): number {
  if (state.starredMatchIds.includes(match.id)) return 400;
  if (state.followedPlayerIds.includes(match.home.id) || state.followedPlayerIds.includes(match.away.id)) return 300;
  if (state.followedTournamentIds.includes(match.tournamentId)) return 200;
  if (significant(match.round)) return 100;
  return 0;
}
```
